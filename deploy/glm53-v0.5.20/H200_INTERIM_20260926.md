**Шесть профилей: 3762/3762 нагрузочных запроса, 0 ошибок; каждый ответ — 256 токенов.**
P6buckets снизил p95 коротких запросов в постоянном потоке с 2.441 до 1.432 с

окончательный production-профиль пока не утверждён.

Runtime source `4f440e4f5`, upstream v0.5.20. Использован guarded source overlay
поверх пользовательского Harbor-образа, digest
`sha256:b27fce60bc5494c118c4910702812bcfa8cee67abcdd1ff8b0902f21647552f4`.
Новый образ не собирался. Baseline прежнего образа по просьбе пользователя не запускался.

## Условия сравнения

TP8 / CP8 interleave / DCP4 ag_rs / EP8, DP1/PP1, chunk16384, slots40, delay1,
HRRN/adaptive; текущие W4AFP8-веса, Humming, полный DFlash snapshot425aa615…;
FP8 KV, mem fraction0.78. Target KV cap600000 физических /2400000 логических токенов.
HiCache64 GB/rank одинаков во всех опытах, около746 GB вместе с indexer и draft на8 ranks.
Prefill buckets8192/16384; только P6buckets расширяет набор до4096/8192/12288/16384.
Seeds531620/532620/533620, temperature0, ignore_eos, output256.
Каждый профиль: три повтора × пять сценариев, 627 запросов.

P2 — scheduler/adaptive, legacy indexer, KV-gather, sync HiCache.
P3 добавляет compact indexer/workspace1GiB к P2; P4 добавляет Q-stream к P3.
P5 проверяет pipelined HiCache на P3, P6graph — tile graphs на P4.
P6buckets меняет только buckets относительно P2.

Перед P6buckets клиент дополнен сохранением native meta_info и завершающим GET /metrics.
Расписание, входы, seeds, concurrency и sampling не менялись; SHA256 версий сохранены.
Генерация проверяется отдельным точным nonce с natural stop до нагрузки.

## Очередь и прогресс длинного

В P2 и P6buckets все18/18 коротких запросов в mixed ответили до первого токена
длинного; все длинные завершились. Это подтверждает interleaving в этих нагрузках,
но не устранение очереди при любой интенсивности.

Постоянный поток: short p95 P2=2.718/2.365/2.441 с,
P6buckets=1.573/1.388/1.432 с — улучшение во всех трёх парных повторах.
Short E2E p95 median39.02 →29.38 с. Long TTFT median8.709 →8.491 с.
Long E2E median35.365 →32.424 с, однако второй парный повтор ухудшился
27.095 →36.722 с. Безусловную non-regression для long/decode пока не заявляем.

В TP0 логах P2 порции4k/12k выполнялись eager, а в P6buckets — graph.
Это поддерживает причинное объяснение выигрыша на постоянном потоке;
на fresh128k, где16k уже захватывался, выигрыш ~1.4%.
В смешанном сценарии short p95=4.882 против4.916 с, практически без изменения.

## Неудачные оптимизации: причины

P3/P5 не показали устойчивого общего ускорения≥5%. Для одного длинного запроса
compact не уменьшает ширину logits; в профиле KV-gather двух шагов TP0
indexer logits13ms/top-k6.5ms на kernel span1364ms. Они не доминируют в этой нагрузке.

Q-stream eager fresh14.15 с, с tile graphs11.24 с против KV-gather5.71 с.
Payload FP32 reduce-scatter по64 головам — суммарно1GiB на rank/слой/16k чанк;
packed prefix112k —71.75MiB. Графы сокращают расходы запусков, но не этот объём.
Увеличение tile само по себе объёмную причину не устранит.
[Разбор Q-stream с первичными источниками](QSTREAM_ANALYSIS_20260926.md).

В KV-gather trace NCCL kernels суммарно475ms (reduce-scatter264ms,
all-gather205ms), Humming278ms, sparse attention132ms. Суммы могут перекрываться,
это не независимые доли клиентского TTFT и не SM occupancy.
[KV-gather trace](p6buckets-trace-summary.json) · [Q-stream trace](p6graph-trace-summary.json).
PyNccl NVLS off/on на8H200 выполнен: корректность прошла, ускорения нет,
NCCL по-прежнему выбирает Ring/Simple. Сопоставление trace ranks показывает
значимое ожидание позднего MoE. Следующая диагностика снимает expert counts
без балансировки или изменения весов. [Причинный разбор](COLLECTIVE_ANALYSIS_20260926.md).

## Корректность, память, сохранность

57 CPU tests +23 subtests; compact3 CUDA cases; Q-stream4 уникальных случая
на каждом из4 ranks, eager/graph, native Q8 и FP32, допуски не менялись.
Это kernel-level gates, а не полная quality/parity проверка GLM.

Дополнительно49 cache-запросов: P3/P5 восстановили130816 host tokens при0 device hit,
но exact32-token synthetic output gate не прошёл. Cold-repeat тоже расходится
с cold на24-м токене, device-hit — на31-м. Генерация не доказывает ни повреждение,
ни bitwise-correctness host KV. Нужен tensor/reference gate.
Всего3762 performance +49 cache +2 profiling +7 smoke=3820 внешних запросов;
внутренние health/warmup не включены.

P2 sampled free GPU minimum10.6GiB; P6buckets8.44GiB. Выборки каждые30с
не доказывают абсолютный пик. CUDA OOM в завершённых профилях не было.
Все архивы и файлы проверены SHA256: P2/P3/P4/P5/P6graph/P6buckets —
88/116/85/112/85/85 файлов; каждый из двух profiler snapshots —11 файлов.
P6buckets сервер остановлен после экспорта; NVLS probe завершён и экспортирован (17 файлов SHA256).
Сейчас запускается диагностический p7-expertstats-r1 для сбора expert counts.
PVC, веса, compile caches и результаты сохранены. Полномочия на автономное
продолжение получены; прежний approval blocker отсутствует.
